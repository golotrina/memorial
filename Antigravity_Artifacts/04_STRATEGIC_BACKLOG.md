# 04. СТРАТЕГИЧЕСКИЕ ИННОВАЦИИ И ТОЧКИ РОСТА (STRATEGIC BACKLOG)

Документ описывает продвинутые технологические решения для масштабирования агентства на этапах Фазы 2 и Фазы 3. Эти фичи направлены на увеличение LTV (Lifetime Value) клиента и снижение барьера входа.

## 1. Решение проблемы контента: ИИ-Интервьюер (Voice-to-Biography)

Для продуктов «Мемориалы» и «Древо» главной проблемой является неумение клиента писать связные тексты.
*   **Идея:** Внедрение Telegram-бота «TanGo Memory Assistant».
*   **Реализация:** Бот задает эмпатичные вопросы. Клиент отвечает голосовыми сообщениями (без стресса чистого листа). n8n отправляет аудио в API Whisper для идеальной транскрибации. Затем LLM собирает из ответов готовую профессиональную биографию для мемориала.

## 2. Упрощение Web3: Account Abstraction (ERC-4337)

Для элитных тарифов использование сид-фраз отпугивает возрастную аудиторию.
*   **Идея:** Интеграция смарт-аккаунтов (Account Abstraction).
*   **Реализация:** Клиент авторизуется в админке по обычному Google/Email (социальный логин). Смарт-контракт автоматически создает некастодиальный кошелек "под капотом". Клиенту не нужно знать про блокчейн, чтобы владеть NFT-доменом. Crypto Steel (пластина с ключами) выдается только как хардкорный бекап в VIP-бокс.

## 3. Финансовая воронка: Микро-транзакции (Impulse Upsells)

Добавление магазина микроуслуг внутри клиентской админки (pay-as-you-go) для тех, кто не готов покупать PRO-тариф за $188, но готов потратить $20.
*   **Снятие вотермарки:** Убрать логотип студии за $19.
*   **Эстетика:** Разблокировать анимацию "Вечной свечи" за $12.
*   **PDF-Макет:** Заказать PDF для самостоятельной печати таблички за $9.
Оплата через LiqPay/WayForPay и автоматическое обновление `config.json` на GitHub.

## 4. Генеалогические микро-продукты

На базе парсера Tango Data-Ancestor можно продавать отдельные дешевые услуги:
*   **Авто-раскрашивание метрик:** Пропуск старых черно-белых сканов из архивов через ИИ для улучшения читабельности.
*   **Трансляция дореволюционного текста:** Модель LLM обученная специально на дореволюционном письме переводит текст на современный русский язык.

## 5. Максимальная автоматизация парсинга (Tango Data-Ancestor Pipeline)

Ручной перенос данных из отчетов генеалогов в GEDCOM — это изнурительный труд, от которого отказываются сами генеалоги. Чтобы студия могла продавать эту услугу за $2000-$5000, не тратя на нее месяцы жизни основателя, необходима **Human-in-the-loop (HITL) архитектура**.

**Конкурентный анализ:** 
На рынке существуют программы типа *Transkribus* (для чтения старых рукописей) и корпоративные ИИ Ancestry, но **ни один** публичный SaaS не умеет брать 300-страничный нарративный отчет на русском/украинском языке и превращать его в точный граф GEDCOM с привязкой фото и архивных шифров (Фонд/Опись/Дело) к конкретным тегам `NOTE`. Это абсолютно свободная ниша голубого океана.

**Как автоматизировать это до 1-2 часов работы основателя:**
1.  **Massive Context LLM (Gemini 1.5 Pro / GPT-4o):** Использование моделей с огромным контекстным окном (до 2 млн токенов). В нее загружается весь PDF-отчет целиком (текст + картинки). Промпт заставляет ИИ извлечь данные в строгий формат JSON.
2.  **Собственный UI-Интерфейс (Сплит-скрин):** Разработка закрытого веб-приложения только для Татьяны.
    *   *Слева:* Отображается исходный PDF.
    *   *Справа:* Графическое превью созданного Древа (узлы и связи).
    *   Если ИИ сомневается (например, нашел человека, но не понял, чей это сын), этот узел светится **красным**. Татьяна просто перетаскивает его мышкой (Drag-and-Drop) к нужному родителю.
3.  **One-Click GEDCOM:** После визуальной проверки и перетаскивания узлов нажимается одна кнопка, и скрипт собирает валидный `.ged` файл.
**Результат:** Вместо 40 часов ручного копипаста, Татьяна тратит 40 минут на проверку красных зон и перетаскивание узлов мышкой. Клиент платит премиум-чек за филигранную работу.

## 6. Динамическая Мультиязычность (Dynamic Template Engine)

Для масштабирования продукта на другие рынки (СНГ, Европа) и создания универсального шаблона (Template Engine) требуется уйти от жесткой привязки к 3 языкам (UA/RU/EN).
*   **Идея:** Полностью конфигурационно-управляемая языковая модель.
*   **Реализация:**
    1.  **Централизованный конфиг:** В data.js вводится массив window.SITE_CONFIG.languages с настройками активных языков для конкретного клиента (например, [{ code: 'bg', apiCode: 'bg', label: 'БЪЛ' }, ...]).
    2.  **Динамический интерфейс:** Скрипт pp.js читает конфиг и автоматически генерирует HTML-кнопки переключения языков. Заказчик может запросить хоть 5 языков, и они добавятся без вмешательства в код.
    3.  **Умный автоперевод:** Функция модерации свечей (и биографии) динамически проходит циклом по массиву languages и вызывает Google Translate API для каждого активного языка, формируя JSON-объект message: { ua: "...", bg: "...", kz: "..." }.
*   **Бизнес-ценность:** Позволяет продавать шаблон клиентам из любой страны мира без необходимости ручного рефакторинга кода (zero-code настройка для администратора).
