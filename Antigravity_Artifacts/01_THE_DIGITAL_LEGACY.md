# 01. ПРОДУКТ: THE DIGITAL LEGACY (ЦИФРОВЫЕ МЕМОРИАЛЫ)

**The Digital Legacy** — это сервис автоматизированного создания цифровых мемориалов на базе статического хостинга (GitHub Pages) с привязкой к физическим носителям (QR-табличкам).

## 1. Тарифная сетка и бизнес-логика

| Характеристика | «Автономный старт» (Бесплатно) | «Родовой архив PRO» ($188) | «Цифровое Сияние VIP» ($888+) |
| :--- | :--- | :--- | :--- |
| **Срок выдачи** | До 48 часов | 7–14 рабочих дней | 21–30 рабочих дней |
| **Размещение** | Только GitHub Pages | GitHub + GitLab | GitHub + GitLab + Web3 (Arweave/IPFS) |

| **Физика** | PDF-макет | Стеклянная табличка | VIP-бокс, табличка, Crypto Steel |

## 2. Физические носители и NFC

Отказ от классических металлических/акриловых табличек в пользу премиум-эстетики.
*   **Материал:** Каленое стекло Optiwhite (10х15 или 130×180 мм). Прозрачная кайма по периметру.
*   **Технология нанесения:** УФ-печать (белая подложка + черный текст и QR).
*   **NFC-Hardware:** Строго **Anti-Metal** наклейки NTAG213 или NTAG216 с ферритовым слоем (обычные на граните работать не будут). Закупаются на ID Card или 1wire (Фаза 1), далее оптом на Alibaba (Фаза 2).
*   **Монтаж NFC:** Стикер клеится на обратную сторону стекла прямо по центру белой подложки под QR-кодом перед нанесением защитного лака. Радиосигнал проходит сквозь стекло, делая чип полностью скрытым и защищенным от непогоды и вандализма.
*   **Архитектура записи (Multiple NDEF Records):** Для исключения зависимости от одного хостинга (единой точки отказа) применяется многослойная запись данных на чипы высокой емкости (NTAG216):
    *   *Primary Record (URI):* Прямая ссылка на GitHub Pages для мгновенного автоматического открытия на современных смартфонах.
    *   *Secondary Record (Text):* Текстовая запись с децентрализованным хэшем мемориала (например, `Arweave ID: [hash]`). При недоступности основного сервера в будущем, данные можно будет извлечь через специализированные NFC-ридеры.
*   **Визуальный бэкап (VIP):** На физическом носителе микрошрифтом дублируется Web3 Archive ID (Arweave Hash).
*   **Программирование (Фаза 1):** Осуществляется смартфоном через бесплатное приложение `NFC Tools`. Обязательно использование функции **Set as read-only (Lock)** после успешной записи многослойной структуры, чтобы предотвратить перезапись чипа посторонними.
*   **Автоматизация (Фаза 2):** Программирование в 1 клик с помощью настольного USB-ридера ACS ACR122U и скрипта (Node.js/Python), интегрированного в CRM студии.

## 3. Web3 и Автономность мемориалов

Главное УТП проекта — **Абсолютная автономность (Long-term preservation)**.
*   Регистрация аккаунтов на GitHub/GitLab производится **только по Email/Password** (строгий отказ от OAuth "Войти через Google", так как Google удаляет почту через 2 года).
*   **Обязательная 2FA:** Генерируются 10 Recovery Codes. Они вписываются в физический Сертификат Владельца.
*   **Web3 уровень (VIP):** Мемориал упаковывается и отправляется в Arweave (сеть вечного хранения, $3-5 за ГБ на 200 лет). Клиент получает 12 слов сид-фразы на огнеупорной пластине Crypto Steel.

## 4. Инженерное решение (Скрипт развертывания репозитория)

Когда клиент заполняет форму на главном сайте (и оплачивает тариф), webhook дергает наш бэкенд (n8n или Vercel Serverless Function).
Бэкенд должен взять **Template Repository** (в котором уже лежит HTML/CSS/JS мемориала) и клонировать его в новый репозиторий для клиента через GitHub API.

### [АЛГОРИТМ]: Node.js скрипт деплоя мемориала

```javascript
// deploy_memorial.js
const axios = require('axios');

async function createMemorialRepo(clientSurname, githubToken) {
    const orgName = "the-digital-legacy"; // Название вашей организации в GitHub
    const templateOwner = "the-digital-legacy";
    const templateRepo = "memorial-template-v1"; // Шаблонный репозиторий мемориала
    
    // Генерируем уникальное имя репозитория (например, ivanov-family-legacy)
    const newRepoName = `${clientSurname.toLowerCase()}-family-legacy`;

    try {
        console.log(`[🚀] Запуск деплоя мемориала для семьи: ${clientSurname}...`);
        
        // 1. Создание нового репозитория из шаблона (POST /repos/{template_owner}/{template_repo}/generate)
        const createRes = await axios.post(
            `https://api.github.com/repos/${templateOwner}/${templateRepo}/generate`,
            {
                owner: orgName,
                name: newRepoName,
                description: `Digital Memorial for the ${clientSurname} family`,
                include_all_branches: false,
                private: false // Мемориал должен быть Public для попадания в Arctic Code Vault
            },
            {
                headers: {
                    'Authorization': `token ${githubToken}`,
                    'Accept': 'application/vnd.github+json'
                }
            }
        );

        console.log(`[✅] Репозиторий ${newRepoName} успешно создан!`);
        
        // 2. (Опционально) Настройка GitHub Pages для нового репозитория
        // POST /repos/{owner}/{repo}/pages
        await axios.post(
            `https://api.github.com/repos/${orgName}/${newRepoName}/pages`,
            {
                source: {
                    branch: 'main',
                    path: '/'
                }
            },
            {
                headers: {
                    'Authorization': `token ${githubToken}`,
                    'Accept': 'application/vnd.github+json'
                }
            }
        );

        console.log(`[✅] GitHub Pages активированы. Ссылка: https://${orgName}.github.io/${newRepoName}`);
        return `https://${orgName}.github.io/${newRepoName}`;

    } catch (error) {
        console.error("[❌] Ошибка деплоя:", error.response ? error.response.data : error.message);
        throw error;
    }
}

// Пример вызова (в реальности токен берется из .env, а фамилия из Webhook формы)
// createMemorialRepo("Ivanov", process.env.GITHUB_TOKEN);
```

Этот скрипт позволяет полностью автоматизировать техническую рутину. Клиент оплатил -> скрипт создал сайт за 5 секунд.

## 5. Архитектурный манифест (Медиа и Внешние ссылки)

Для сохранения абсолютной автономности и вечности мемориалов накладывается **строгий запрет** на использование прямых гиперссылок на сторонние платформы (MyHeritage, Ancestry, YouTube) внутри "Линии Жизни". Внешние ссылки подвержены "Link Rot" (ошибка 404 через 10-15 лет).

### Правило 1: Инфографика вместо ссылок (MyHeritage)
Вместо того чтобы давать ссылку на результаты ДНК или этнической принадлежности на сайте MyHeritage:
*   Делаются качественные скриншоты карт и процентов кровей.
*   Изображения конвертируются в легкий формат **WebP**.
*   Встраиваются напрямую в HTML-код как эстетичный блок "Этническое наследие".

### Правило 2: Локальное интерактивное Древо (Premium)
Вместо внешней ссылки на древо MyHeritage:
*   Генеалогические данные хранятся локально в файле `tree.json`.
*   Скрипт на чистом SVG/JS отрисовывает интерактивное дерево прямо в интерфейсе мемориала, по ветвям которого можно кликать.

### Правило 3: Нативные модальные окна для Видео (Zero-JS)
Чтобы не раздувать вес репозитория и избежать YouTube-трекеров:
*   Видеофайлы (.mp4) хранятся на децентрализованных хранилищах (IPFS/Arweave) или выделенном облаке.
*   Триггером в тексте выступает аккуратный `<span class="inline-video-trigger">` с SVG-иконкой Play или WebP-превью.
*   При клике видео открывается в нативном HTML5 элементе `<dialog>` поверх размытого фона (`backdrop-filter: blur`).
*   Тег `<video>` обязательно использует атрибут `preload="none"`, чтобы не тратить мобильный трафик посетителя до момента клика.
